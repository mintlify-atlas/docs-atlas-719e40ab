Phase 4 is where the landing page comes to life. Claude writes every file without stopping to ask for approval — the full page is built, then you review it in Phase 5. This approach produces a complete, coherent result rather than a patchwork of individually approved fragments.

## What Phase 4 Produces

Claude writes three categories of files inside `site/src/`:

- **`app/layout.tsx`** — Next.js root layout: font loading, metadata export, body wrapper
- **`app/page.tsx`** — the landing page itself, assembled from components
- **`components/`** — individual section components (Hero, Features, Testimonials, etc.)

All files use the design system tokens, font choices, and archetype structure finalized in Phase 2. Nothing is hardcoded — colors come from CSS custom properties, fonts from `next/font/google` variables, spacing from the fluid scale.

## Next.js App Router Structure

```
site/src/app/
├── layout.tsx     ← Google Fonts, metadata object, body className
├── page.tsx       ← Landing page: imports and orders section components
└── globals.css    ← Token values updated to your brand colors and fonts
```

### `layout.tsx` — Fonts and Metadata

```tsx
import { Space_Grotesk, DM_Sans } from "next/font/google";
import type { Metadata } from "next";
import "./globals.css";

const display = Space_Grotesk({
  subsets: ["latin"],
  variable: "--font-display",
  display: "swap",
});

const text = DM_Sans({
  subsets: ["latin"],
  variable: "--font-text",
  display: "swap",
});

export const metadata: Metadata = {
  title: "Acme Studio — Design That Moves",
  description: "We build brand identities for companies that want to be remembered.",
  openGraph: {
    title: "Acme Studio — Design That Moves",
    description: "We build brand identities for companies that want to be remembered.",
  },
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body className={`${display.variable} ${text.variable} antialiased`}>
        {children}
      </body>
    </html>
  );
}
```

<Note>
  Claude overwrites the default `body { font-family: Arial, Helvetica, sans-serif }` that `create-next-app` hardcodes. Arial is on the banned font list. The Google Fonts variables set in `layout.tsx` are bridged to utility classes through `globals.css`.
</Note>

### `page.tsx` — The Landing Page

`page.tsx` is kept as a Server Component where possible. Components that use `useState`, `useEffect`, event handlers, or Motion animations include `"use client"` at the top of their file.

## How Copy Is Written

Every piece of text on the page goes through the `humanizer` skill before it's written into any file. This removes the vocabulary patterns that make AI-generated copy sound like AI-generated copy.

**Banned words and phrases:**
> delve, tapestry, landscape, foster, showcase, vibrant, nestled, leverage, innovative, cutting-edge, game-changing, seamless, empower, harness, spearhead, holistic, synergy, robust, dynamic, elevate, transform, revolutionize, reimagine, curate, bespoke

**Banned patterns:**
- "In a world where..." or "In today's [adjective] landscape..."
- Every sentence being the same length
- Em dash overuse — especially multiple per paragraph — like this
- Ending sections with "The future of [topic] is bright"
- Vague authority: "Experts say..." / "Many believe..."

**What good copy looks like instead:**
- Specific. Numbers, names, real details.
- Opinionated. "We build fast" beats "We deliver innovative solutions."
- Varied rhythm. Short punchy lines. Then longer ones that give the reader room to absorb what you just said.
- Conversational. "You" and "we" — not a press release.

## Standard Section Order

Unless your archetype specifies otherwise, sections follow this sequence:

1. **Navigation** — logo, 2–3 links, CTA button
2. **Hero** — headline, subheadline, primary CTA
3. **Social Proof Strip** — logos, a key metric, or trust badges
4. **Features / Services** — 3–4 items in a varied layout (not identical cards)
5. **Testimonials** — 1–3 quotes with names and roles
6. **CTA Section** — repeat the main call to action
7. **Footer** — contact info, social links, and the footer credit

The exact order is determined by your chosen archetype from Phase 2. Claude tells you which archetype it's using: *"Based on your consulting business, I'm using the Social-Proof-Heavy pattern because trust signals need to come before the ask."*

## Contact Form Options

<Steps>
  <Step title="Simple mailto: (default)">
    A contact section styled as a call-to-action with a "Send us an email" button. No backend needed — clicking opens the user's email client.

    This is the default if you said you want a contact option but didn't specify which kind.
  </Step>
  <Step title="Formspree (no backend needed)">

    <Note>
      Every form field has a visible `<label>` element — placeholder text alone doesn't satisfy accessibility requirements.
    </Note>
  </Step>

## Accessibility Built In

Claude writes semantic HTML throughout — not just generic `<div>` containers:

- `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>` for document structure
- One `<h1>` (the hero headline), then `<h2>` and `<h3>` in order — no skipped levels
- `alt` text on all informative images, `alt=""` on decorative ones
- `aria-label` on icon-only buttons
- Focus order matching visual order
- All interactive elements keyboard accessible
- WCAG AA contrast: 4.5:1 for body text, 3:1 for large text
