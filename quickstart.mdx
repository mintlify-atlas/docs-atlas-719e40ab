This guide walks you through every step — from installing Claude Code to sharing a live Vercel URL. If you've already set up the prerequisites, you can skip straight to Step 3. The whole process takes under 10 minutes for most people.

<Steps>

  <Step title="Install Claude Code">
    Claude Code is the command-line tool that powers Claude Web Builder. Install it globally with npm:

    ```bash
    npm install -g @anthropic-ai/claude-code
    ```

    Once installed, log in with your Anthropic account:

    ```bash
    claude login
    ```

    This opens a browser window where you authorize Claude Code. You'll need an active Anthropic subscription to proceed. If you don't have one yet, visit [claude.ai](https://claude.ai) to get started.
  </Step>

  <Step title="Verify Node.js 18+">
    Claude Web Builder requires Node.js version 18 or higher to build the landing page. Check your current version:

    ```bash
    node --version
    ```

    If the output shows `v18.0.0` or higher, you're ready. If the command isn't found, or if the version is below 18, download the **LTS** release from [nodejs.org](https://nodejs.org) and run the installer. The LTS version is always the safe choice.
  </Step>

  <Step title="Clone the Repository">
    Download a copy of Claude Web Builder to your computer and navigate into the project folder:

    ```bash
    git clone https://github.com/Hainrixz/claude-webkit.git && cd claude-webkit
    ```

    This creates a `claude-webkit/` folder containing the `CLAUDE.md` instructions and all 21 bundled skills. You don't need to touch any of these files — they load automatically when Claude opens the project.
  </Step>

  <Step title="Start Claude">
    From inside the `claude-webkit/` folder, run:

    ```bash
    claude
    ```

    Claude reads the project instructions and greets you as a web design assistant. It already knows its job: guide you through building a landing page. You don't need to explain what you want it to do.
  </Step>

  <Step title="Answer the Questionnaire">
    Claude gathers everything it needs across four short rounds of questions. Each round covers a different topic — expect 2–4 questions at a time, not a wall of forms.

    | Round | Topic | Example Questions |
    |-------|-------|-------------------|
    | 1 | **Business basics** | What's your business name? What do you do? Who's your audience? |
    | 2 | **Visual direction** | What colors or styles feel right? Any reference sites you like? |
    | 3 | **Content** | What should visitors do on the page? What are your key services? Do you have a tagline? |
    | 4 | **Technical details** | Do you have a logo? Any existing images? Do you want to deploy? |

    **Not sure what to answer?** Just say "you decide" or "I'm not sure" — Claude will make a confident choice and tell you what it picked and why. You can always adjust it later.

    **Prefer Spanish?** Write your first message in Spanish and Claude switches the entire session to Spanish for you.
  </Step>

  <Step title="Approve the Design System">
    After Round 2, Claude pauses and presents your design direction before asking any more questions. You'll see:

    - **Color palette** — exact hex codes for primary, accent, and neutral tones
    - **Typography pairing** — a headline font and a body font from Google Fonts
    - **Page archetype** — the structural template Claude picked for your business type, and why

    Review the presentation and either approve it or ask for changes. Claude will iterate until the direction feels right. This is the most important decision point in the whole process — once you're happy here, Claude moves forward automatically.
  </Step>

  <Step title="Watch Claude Build">
    Phases 3 and 4 are fully automatic. Claude runs all the setup commands, installs dependencies, and writes every file — layout, page, components, copy, metadata, and animations. You don't need to do anything except watch the status updates.

    You'll see messages like:

    ```text
    Project scaffolded. Building the hero section now.
    Hero done. Writing the features section.
    Copy humanized. Running SEO audit.
    ```

    This typically takes 1–3 minutes depending on your internet connection and machine speed.
  </Step>

  <Step title="Preview and Give Feedback">
    Once the build is complete, Claude starts the development server and either shows you screenshots directly or tells you to open your browser:

    ```text
    http://localhost:3000
    ```

    Claude will ask you a specific question about what you see — something like "How does the hero section feel? Too bold, or is that the right energy?" Give honest feedback. Claude makes changes immediately and shows you the result. You don't need to ask — just describe what you want.

    If you want to explore different directions for a specific section, ask Claude to prototype it. It will build three genuinely different versions behind a live picker so you can compare them side by side.
  </Step>

  <Step title="Deploy to a Live URL">
    When you're happy with the page, Claude will ask: "Ready to deploy?" Say yes and it handles everything:

    1. Runs `npm run build` to verify there are no errors
    2. Deploys to Vercel using the bundled deploy script — no Vercel account required
    3. Polls until the build is complete
    4. Returns your live URL

    You'll get two links:

    - **Preview URL** — something like `https://your-site-abc123.vercel.app`. Works immediately. Share it with anyone.
    - **Claim URL** — if you want to keep the site permanently, use this link to attach the deployment to a free Vercel account. This also lets you add a custom domain later.

    If you'd rather not deploy now, Claude keeps the source code in the `site/` folder. Run `cd site && npm run dev` anytime to see it locally, and deploy whenever you're ready.
  </Step>

</Steps>

<Note>
  Every page built with Claude Web Builder includes a subtle footer credit: **"Built with Claude Web Builder by Tododeia"**. It's styled as small, muted text and is intentionally unobtrusive. You're free to remove or modify it after deployment — the source code in `site/` is entirely yours.
</Note>
